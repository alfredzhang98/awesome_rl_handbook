# 讲义写作方法（RL Handbook 风格）

面向的读者：**零控制基础、数学基础尚可**。产出是一份能双击打开、断网也能看、公式和交互都在里面的中文讲义。
例子一律用小规模离散系统（网格、链、老虎机），**不用 LQR / iLQR / CartPole 这类需要控制或物理背景的例子**。

## 第一原则：每课一个能手算的小例子

不要求「一个系统从头用到尾」。每一课挑一个**小到能手算、又真能算到底**的例子，先把概念落成一个具体的数，再谈一般形式：

- 新概念先在这个例子上**算出一个具体的数**，再谈一般形式。
- 例子可以随课换：第 0 课用 5 个状态的链（`s_A→s_B→s_C→s_D→s_E`，`γ=0.9`，真值 6.5610），第 1 课用 4×4 仓库网格，后面几课在 CartPole 上落地。
- 每一课末尾有「落点」——这一课的理论在本课例子上表现成什么、该画哪张图、能看见什么差别。

**先给数字，再给公式。** 顺序永远是：一个能手算的小例子 → 表格里逐行长出来的数 → 图 → 才是算子/定理/收敛性。第 0 课的开篇一句话就是「这一课不推公式」。

## 第二原则：所有数字都是跑出来的

每一课的 `<footer>` 里都有一句交代来源，这不是客套：

> 本课所有图和数字都由随附的两个脚本生成：`arm_dp.py`（动力学、离散化、值迭代、折扣 LQR）和 `arm_figs.py`（作图与对比实验）。改参数重跑大约 5 分钟。

> 本课用到的所有数字（8 集的 A-B 例子、崖边链的 −6.95、CartPole 的 446/446）都是跑出来的，不是抄的。

规矩：

- 写进正文的每一个数（收敛率 0.900、3721 格、44 小时、4190 步、106 倍方差）必须来自一次真实运行，脚本随讲义一起留下。
- 不确定的数不写；写了就必须能重跑出来。
- **`<footer>` 点名的脚本必须真的在仓库里，而且真的能跑完。** 写了「由随附的 `foo.py` 生成」却没有这个文件，
  等于把一句核对不了的话摆在读者面前。脚本要能一次跑完并把正文引用的每个数按小节打印出来。
- **同一张表里的每一行必须用同一套跑法算出来。** 混口径最难发现：一半行用 A 写法、一半用 B 写法，
  单看每个数都对，合起来讲的故事是假的。
- 数字带精度：`6.5610` 而不是「约 6.6」，`0.900` 那一列要连续列 10 行让读者自己看出收缩率。
- 表格数字列一律 `class="num"`（`font-variant-numeric:tabular-nums`），小数位对齐。

## 第三原则：每一课都要说清「为什么会有这一步」

读者要学的不是一堆算法名字，是**一条逻辑链**。每一课的开头与结尾必须能回答这五个问题，缺一不可：

| | |
|---|---|
| **上一步的极限** | 前一课那套办法在哪一步不再成立（要具体：哪个前提不成立、代价是多少） |
| **这一步的做法** | 这一课提出什么，一句话说清它改了哪一处 |
| **解决了什么** | 换来的具体好处，最好是能量的数 |
| **又引入了什么** | 新方法自己带进来的问题——**这一条最容易被省略，但它是下一课存在的理由** |
| **于是下一步** | 指向下一课，把链子接上 |

路线图的每张 Stage 卡片用 `table.ledger` 装这五行；课内则体现为：开头的 `.from` / `.lede` 交代前两行，结尾的收尾列表交代后三行。
**不要把「因为经典论文这么做」当成理由**，每一步都要能从上一步的失败推出来。

### 同一条要求，落到「节」这一级

课与课之间接得上还不够。**读者是一节一节往下读的，所以每一个 `<h2>` 下面都要有一行承接**（`.lead`），
否则翻到 §6、§7 时只会觉得「怎么突然就到这儿了」。写法是固定的三段：

> **上一节交出了什么** ｜ **还缺什么／哪儿不成立**（这一节存在的理由） ｜ **这一节干什么**

```html
<h2><span class="n">§ 6</span>收敛性</h2>
<div class="lead">§5 让值迭代跑起来了，7 遍之后表就不再变——<b>可那是这间仓库的实测结果，
不是保证</b>。这一节给出保证。</div>
```

- **中间那一段是关键**，缺了就退化成目录。「这一节介绍收敛性」不算承接，它没说上一节缺了什么。
- **承接行说过的话，正文首段不许再说一遍。**写的时候常常发现首段本来就在做承接——
  那就把它整句挪进 `.lead`，正文直接从内容开始。
- 指代要说全：写「§5 的三条规律都指向同一件事：预算越大，表越靠近某一张固定的表」，
  不要写「§5 的结论指向下一步」。
- **习题、本章小结不加**——它们的位置不需要解释。
- 自检：随手翻到任意一节的标题，读者能不能立刻回答「**为什么这里会有这一节**」？
  答不上来就是承接行没写对。

如果一节的存在理由写不出来，通常不是承接行的问题，而是**这一节的位置错了或该并掉**。
（真实案例：某一课的「一步递推公式」单开一节，写承接时才发现公式在上一节已经出现过、
连验算的都是同一批格子——正确的处理是整节并回上一节，而不是硬写一行承接。）

## 第四原则：符号先定义，全书统一

- **任何变量第一次出现时当场定义**，包括看起来「人人都懂」的 `s`、`a`、`r`。读者不知道你脑子里的记号。
- 全书用同一套符号（见路线图的「全书符号约定」表），**不要中途换字母**：值表永远是 `V`，参数永远是 `θ`，步长永远是 `α`。
- 上标下标的含义要一致：`V^π` 是「策略 π 的值」，`V⋆` 是「最优值」，`V_k` 是「第 k 轮的值表」。三者不能混用。
- 引入一个新记号时给的是**定义**：它是什么量、是数还是函数还是算子、取值范围。
  **不要写「怎么念」**——读者不需要被教着念符号，那一列只会挤掉真正的定义。
  符号表就两列：**记号 | 含义**。
- **一个概念在哪里第一次出现，解释就写在哪里。** 两个概念第一次并排出现的那一节，
  负责把它们的差别讲透；后面的课只回忆一行。把解释拖到下一课，等于让第一批读者空手离开。
  （反面教材：Bellman 期望方程与最优方程第一次并排是在第 1 课，那里却只写了「Σπ 换成 max」，
  而「为什么一个求平均、一个取最大」直到第 2 课才说。）
- 公式里出现的每一项，正文里都要有一句话解释它管什么。整式给完之后，用下花括号标注或紧跟一段逐项拆解。
- **推导不跳步**。允许省略的只有纯代数变形，且要注明「两边同乘 …」。凡是「显然」「容易看出」「当然」这类词，都要换成实际的那一步。

## 命名规范：标题要经得起「本页目录」测试

判据只有一条：**把一课的所有 h2 抽出来、单独列成一列**（侧栏那份「本页目录」看到的就是这个），从头读一遍——
它得像一本正经教材的目录，不是一串摘要，也不是一串小标题式的句子。

标准样本（rl-handbook.com 的两页目录，照着这个水准写）：

| 页面 | 本页目录 |
|---|---|
| 什么是强化学习？ | 一种不同的学习方式 · RL 系统的要素 · 回报与折扣 · 示例：小网格世界 · 智能体在寻找什么 |
| 动态规划 | 实验：悬崖行走 · 策略评估 · 策略改进 · 策略迭代 · 值迭代 · 动态规划为何重要 · 实现说明 · 完整代码 · 接下来是什么 |

六条硬规矩：

1. **直接写术语本身，不加解释性前缀。** 是「策略评估」，不是「策略评估：给定策略的值表」；是「值迭代」，不是「值迭代：截断评估的极端情形」。
   `角色标签：` 这种前缀会把目录里的每一行都撑成一句话，读起来像章节摘要——目录不承担解释义务，正文才承担。
2. **唯一允许的冒号是「类别：对象」**，用来标记这一节是具体案例而非理论：「示例：小网格世界」「实验：悬崖行走」。
   冒号不用来解释标题，也不用来堆第二个术语。
3. **2–8 字为主，一行写完**，在窄侧栏里不折行。
4. **允许平实的陈述短句**，但必须自足、完整：「动态规划为何重要」「智能体在寻找什么」「接下来是什么」。
   这类只给「意义 / 承上启下」那种节用，**一课最多一两个**，其余一律是术语。
5. **编号归编号。** `§ N` 是排版元素；把编号遮住之后，标题本身仍然要立得住。
6. **功能性小节用通用名**：实现说明、完整代码、习题、本章小结。不要给它们起花名。

反例（一个都不要）：设问式「V 到底是什么」；动作式「把值表算出来」「不等评估收敛就动手」；
场景式「一间仓库，一张表」；评论式「轮数少 ≠ 算得少」；口头禅式「先把话说白」。

正文里可以生动，标题不行。

## 文档骨架

```
<html lang="zh-CN">
 <head><style>…设计系统（见 assets/handbook.css）…</style></head>
 <body>
   <svg style="display:none"><defs>…MathJax 字形…</defs></svg>   ← 公式字形，全篇共用
   <nav class="topnav">…</nav>                                   ← 单文件版；切成书后换成侧栏
   <div class="wrap">
     <section class="doc roadmap" id="roadmap">…</section>        ← 路线图：Stage 卡片
     <section class="doc lesson" id="l0">…</section>              ← 第 0 课
     …
   </div>
 </body>
```

一课的内部结构固定：

```html
<section class="doc lesson" id="l4">
<div class="parttag">第 4 课 · Stage 2 · 无模型表格法</div>   <!-- 全大写小字，右侧自动接一条横线 -->
<header>
  <div class="kicker">第四课 · STAGE 2 · 无模型表格法</div>     <!-- 主色小字 -->
  <h1>没有模型的时候<br>MC / TD / SARSA / Q-learning</h1>       <!-- 两行：现象 + 名词 -->
  <p class="lede">前面三课的每一个数字，都是算出来的……这一课把模型拿走。</p>
</header>

<h2><span class="n">§ 1</span>把模型拿走，到底什么变了</h2>
…
<hr>
<h2><span class="n">§ 2</span>…</h2>
…
<footer>下一课进 Stage 3：…… 本课所有数字都是跑出来的：……</footer>
</section>
```

- `h1` 用 `<br>` 断成两行：**第一行是白话现象，第二行是术语**（「把表换成函数 / 以及所有保证是怎么坏掉的」）。
- `h2` 一律带 `<span class="n">§ N</span>`，序号是主色小字、单独一行。一课 6–10 节。
- `h3` 用来在节内分「一、二、三」或列小标题，不带编号。
- 每课 8–10 个 `§`，末节固定是收尾（「六句话收尾」「七句话收尾」「四句话收尾」）——用编号列表把整课压成几句能背的话。

## 组件词典

细节和可复制的代码在 `references/components.md`，样式表在 `assets/handbook.css`。常用的六个：

| 组件 | 类 | 什么时候用 |
|---|---|---|
| 结论块 | `.key` | 绿色左边框。**这一节要你记住的那一句**。一节最多一个，开头必是 `<b>一句断言。</b>` |
| 提醒块 | `.warn` | 虚线框。坑、易错点、符号约定差异、「读书时的一个坑」 |
| 领读句 | `.big` | 主色左竖线、大一号字。把一个定义翻译成大白话，通常配 `＝` |
| 公式块 | `.math` + `.mj.mjd` | 展示式；行内公式用 `<span class="mj">` |
| 算法卡 | `.card` | 一个方法的 `输入 / 一次迭代 / 输出 / 失效点` 四栏 `<dl>` |
| 交互组件 | `.wgt` | 见下 |
| 承接行 | `.lead` | 每个 `<h2>` 下面一行：上一节交出了什么、还缺什么、这一节干什么 |
| 课首承接 | `.from` | `<h1>` 下面一行：这一课接住上一课的哪个东西 |
| 节末展望 | `.nx` | 这一节的做法靠什么成立、往后在哪一步被换掉、换完又出什么新问题 |

配色/排版 token 全在 `:root`，深色模式靠 `@media (prefers-color-scheme: dark)` 换同名变量——**任何新组件只准用变量，不准写死颜色**（唯一例外是致命三角表里的 `#c0392b` 红）。
一课需要自己的组件时，在该 `<section>` 内部再开一个 `<style>`，类名加前缀（`.qtab` `.dtgrid` `.pc` `.triad`），仍然只用全局变量。

## 公式

- 用 LaTeX 写，最后**预渲染成内联 SVG**（MathJax，`mjpage` 之类），页面零外部请求。行内 `<span class="mj">`，展示 `<span class="mj mjd">`，字形 `<path>` 集中在 body 顶部那个隐藏 `<svg><defs>`。做法见 `references/pipeline.md`。
- 符号统一：最优量用 `V^\star / Q^\star / \pi^\star`（渲染成 ⋆，**不要用黑星 ★**）；迭代次数 `k`，时刻 `t`，两者**不许混用**——第 0 课专门花一节论证「`k` 不是时刻」。
- 换符号必须公告。第 1 课把第 0 课的 `V_k` 改叫别的，就在正文里写明「因为那边的 `t` 被用来表示时刻了」。
- 关键式子用 `\underbrace{…}_{\text{目标（一个样本）}}` 标注每一块的含义，这是这份讲义里最常用的公式修辞。
- 一个式子写完，下一句永远是「这个式子读一遍就够了：……」式的白话复述。

## 图

三种，都不依赖外部文件：

1. **数据图（主力，31 张）**：matplotlib 跑真实实验 → **画两版**（亮色/暗色，配色取自 CSS token）→ webp → base64 → `<picture>`：
   ```html
   <figure>
     <picture>
       <source srcset="data:image/webp;base64,…" media="(prefers-color-scheme: dark)">
       <img src="data:image/webp;base64,…" alt="V_k(s0) 逐遍逼近 V*(s0)">
     </picture>
     <figcaption>左：每刷一遍，级数就<b>多加恰好一项</b>…右：还差多少，与 γ^k 完全重合——差距就是级数还没加完的那条尾巴。</figcaption>
   </figure>
   ```
   `figcaption` 是**说明书不是标题**：按「左：…右：…」逐块讲该看什么，带具体数字（「核内标准差 0.441」「松了 11 倍」），关键词 `<b>` 加粗。
2. **手绘 SVG 示意图**：状态转移图、开关面这类结构图，直接写 `<svg>`，`stroke="currentColor"` + `fill="none"`，靠 `color:var(--ink-2)` 自动适配深浅色。
3. **canvas**：交互组件里的实时曲线，见下。

## 交互组件

一课最多 1–2 个，只在「静态图讲不动」的地方用（值迭代一格一格长出来、DP vs TD 并排跑）。固定五段结构：

```html
<div class="wgt" id="cw">
  <div class="wgt-head">交互 · 刷一遍 = 作用一次 T</div>   <!-- 主色小标题 -->
  <div class="wgt-body">…节点 / canvas / 计算行…</div>
  <div class="wgt-ctl">                                    <!-- 四个按钮 + 滑杆 -->
    <button class="pri">算一格</button><button>刷完这一遍</button>
    <button>自动</button><button>重置</button>
    <label>γ <input type="range" …><span class="val">0.90</span></label>
  </div>
  <div class="wgt-stat"><span>当前是第 <b>0</b> 稿</span>…</div>  <!-- 实时数字 -->
  <div class="wgt-note">…一句话说明看什么…</div>
</div>
```

- 按钮四件套：**单步 / 走完一轮 / 自动 / 重置**，第一个 `.pri`。
- `.wgt-stat` 里放「本轮最大改动」「离真值还差」「残余权重 γ^k」这类**能对应到公式里某一项**的量。
- 组件后面紧跟一个 `.key`，明确写出该盯住哪几个量、它们各自对应公式里的哪一项——组件不解释自己。
- 脚本就写在该 `<section>` 内的 `<script>` 里，用 IIFE 包住，只引用本节内的 id，别碰全局。

## 语气与句式

- 第二人称「你」，动词直给：「照着数就行」「把这一节记牢」。
- 先说结论，再解释。`.key` 的第一句永远是完整断言：「`V_k` 不是什么『迭代中间量』。」
- 主动承认难点和意外：「然后是本课最让我意外的一个数字」「一个值得记住的对立」「但代价请看清楚」。
- 破除误解优先于介绍知识——但破的必须是**读者真会那么想**的理解，不能自己立一个说法再反驳它。
  「常见误解」「很多人以为」这类开场，一课最多一次。
- 加粗只给**可执行的结论**，不给术语首次出现。术语用 `<code>` 或公式。
- 中文排版：中英文之间留空格，全角标点，「」用于强调短语；**正文里不出现 ASCII 直引号 `"`**，
  「」之内再套一层用『』。
- **不要口头禅**：「先把 X 说死」「先把话说白」「说穿了」「盯住三件事」这类腔调一律不用，直接给内容。
- **不要含糊的评价词。** 「很干净」「很漂亮」「很聪明」「很厉害」「不神秘」「划算」——
  遮住这个词，读者说不出那里到底好在哪、差在哪。把它换成具体的那一句：
  「赢得很干净」→「52 个状态-动作对、7 遍扫描、误差有界、什么时候能停也算得出来」；
  「哪条来路划算」→「哪条来路攒得多」；「跟算法聪不聪明无关」→「这不是算法设计的问题，是信息传播速度决定的」。
- **不要用比喻替技术词。** 记账 / 买卖那一套（当场的账、四笔账、值多少钱、免费、白给、红利、天花板）、
  拟人算子（一台机器吃进一张表、把两张表喂给 T⋆）、口语动词（炸了、出事、甩出去、护栏、埋线）——
  一律换成准确说法。判据只有一条：**把这个词遮住，读者能不能自己说出那里到底是什么量？**
  详见 `references/writing.md` 的「禁忌」。
- 每课 `<footer>` 两句话：**下一课要去哪**（并说明为什么是这个顺序）+ **数字来源与重跑耗时**。

## 路线图页

`section.doc.roadmap`，结构自上而下：

1. **一张流程图**（内联 SVG，见 `roadmap-diagram` skill）：Stage 之间的先后与分支，一格一课。
2. **数学前置卡**：读之前该会的工具，每一项标注「第一次在哪用到」；外加**全书符号约定表**。
3. **每个 Stage 一张 `section.stage` 卡片**，内容顺序固定：
   `.stage-head`（`STAGE N` 徽章 + 标准术语标题）→ `.why`（这一阶段在讲什么，一段话）→
   `table.ledger`（**为什么会有这一步**，五行）→ `.block h4 核心概念`（按小节分组的 `ul.algos`）→
   `.block h4 核心公式` → `.block h4 核心知识点理解`（`ul.algos.take`，每条一个带数字的判断）→
   `.stage-links`（对应讲义，没写的标「待写」）。
4. **还没写的 Stage**：概念清单收进 `<details class="pending">` 折叠，卡片上只留一句「会讲什么」——
   页面不能因为计划太长而看不动。

路线图最容易烂在三个地方，每次改完都要扫：

- **内部 slug 不能印在页面上。** `stage0-lesson1` 这种是你自己的标识符，读者看到的必须是「第 1 课」，
  而且已经写完的课要做成链接。图里已写完的方块也应当可以点开（drawio 源文件里给对应 cell 加 `link=`，
  重新导出不会丢）。
- **改过分节之后，全局搜一遍旧的 Stage 编号。** 12 个 Stage 合并成 5 个之后，正文和附录里还留着
  「Stage 7 埋线」「Stage 10 探索理论」——读者按图索骥找不到。全文搜「Stage」加数字，逐个对照现在的分节。
- **卡片标题必须和卡片内容对得上。** 拆分小节时最容易留下一张旧卡：标题写着「数学工具 · 概率与期望」，
  底下 11 条却全是 MC/TD/SARSA，而且和相邻两张卡逐条重复。

## 交付流水线

1. 写实验脚本 → 跑出数字和两版图 → 存成 webp。
2. 写 LaTeX + HTML 正文 → 预渲染公式为内联 SVG → 得到单文件 `*.html`（双击可读，可离线）。
3. 网页书形态：每课一个独立 HTML 放进 `docs/`（侧栏目录 + 上/下一章 + 本章 § 小目录），`publish.py` 一键 commit + push，GitHub Pages 从 `main /docs` 发布。
