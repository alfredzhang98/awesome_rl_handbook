# 交稿前自检

## 内容

1. 这一课有没有**一个能手算的小例子**？读者不用跑代码就能验证第一个数字吗？
2. 本课例子（CartPole/…）在这一课里落地了吗？有没有「落点」段落说明该跑什么实验、该看什么差别？
3. 正文里每一个数，是否都能在随附脚本里重跑出来？
4. 先给数字再给公式，还是反了？
5. 有没有至少一处「破误解」——指出读者大概率的错误理解并纠正？
6. 这一课的边界写了吗（什么时候这套东西不成立 / 失效点）？
7. 收尾节在不在？能不能只读收尾就复述整课？

## 结构

8. `parttag / kicker / h1(两行) / lede` 四件套齐了吗？
9. `h2` 都带 `<span class="n">§ N</span>` 吗？一课 6–10 节？
10. `<footer>` 两句话齐了吗（下一课去哪 + 数字来源与重跑耗时）？
11. `.key` 每节 ≤ 1 个，且首句是完整断言？
12. 新加的组件有没有写死颜色？（只准用 `var(--…)`）

## 公式

13. `V^\star` 渲染成 ⋆，正文里没有残留黑星 ★？
14. `k`（迭代）与 `t`（时刻）没有混用；换符号处有公告？
15. 关键式子有 `\underbrace{…}_{…}` 标注？
16. 每个公式后面有一句白话复述？
17. 页面里所有 `xlink:href="#MJX-…"` 都能在 `<defs>` 里找到？

## 图

18. 每张数据图都有亮/暗两版，且尺寸布局一致？
19. `figcaption` 是「左：…右：…」式说明书，带具体数字，而不是标题？
20. `alt` 写了公式含义？

## 交付

21. 断网双击打开：公式显示正常、图能看见、交互能点？
22. 深色模式切一遍，有没有对比度炸掉的地方？
23. 窄屏（手机宽度）看一遍，表格和公式能横向滚动而不撑破页面？
24. 跨章链接、侧栏高亮、上一章/下一章都对？
25. `python publish.py` 跑通、Pages 页面刷新出来了？

## 逻辑链与符号（新增，必查）

26. 开头能不能一句话说清**上一课在哪儿撑不住**？没有就补。
27. 结尾有没有写**这一课自己引入了什么新问题**？这是下一课存在的理由，不能省。
28. 正文里出现的**每一个变量**，是不是都在第一次出现时定义过（含读法与类型）？
29. 符号有没有和前面的课冲突（`V^π` / `V⋆` / `V_k`、`α`、`θ`、`λ`）？
30. 有没有「显然」「容易看出」「不难证明」？有就把那一步补出来。
31. **本页目录测试**：把这一课所有 h2 抽出来单列一行行读——像教材目录，还是像一串摘要？
    有没有「角色标签：」式前缀（冒号只留给「示例：」「实验：」）？有没有设问 / 动作 / 场景 / 评论式的名字？
32. 例子是不是小到能手算，而且**不需要控制或物理背景**？
33. 路线图那张卡片的五行账本（极限 / 做法 / 解决了什么 / 又引入什么 / 下一步）填全了吗？
