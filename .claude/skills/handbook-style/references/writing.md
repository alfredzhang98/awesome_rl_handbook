# 语气、句式与修辞

读者假设：零控制基础、数学基础尚可。例句可直接当模板改写。

## 一课的叙事骨架

```
① 上一课的极限        前一课那套办法在哪一步不再成立（具体到哪个前提不成立）
② 这一课改哪一处      一句话说清新方法动了什么
③ 一个能手算的小例子  网格 / 链 / 老虎机，规模小到能逐格列出来
④ 从例子里读出规律    表格连列多行，让读者自己看出那个数
⑤ 才是形式化          符号先定义 → 方程 → 算子 → 定理 → 误差界
⑥ 在同一个例子上落地  用脚本跑出来的图和数验证前面每一句话
⑦ 边界与新问题        这套东西什么时候不成立、它自己带进来了什么毛病
⑧ N 句话收尾          编号列表，每条一句，最后一条指向下一课
```

第 ⑦ 条不能省。**下一课存在的理由，就写在这一课的第 ⑦ 条里。**

还有一条贯穿全书的位置原则：**一个概念在哪一课第一次出现，解释就写在哪一课。**
两个概念第一次并排出现的那一节，负责把它们的差别讲透；后面的课只回忆一行。
把解释拖到下一课，第一批读者就是空着手离开的。

## 节与节之间：承接行

一课的骨架接得上，不代表读者读得下去——**他是一节一节往下读的**。
每个 `<h2>` 下面写一行 `.lead`，三段式：

> 上一节交出了什么 ｜ 还缺什么、哪儿不成立 ｜ 这一节干什么

```
§5 让值迭代跑起来了，7 遍之后表就不再变——可那是这间仓库的实测结果，不是保证。这一节给出保证。
§6 里两条曲线最后都停在一个不为零的水平上，再多跑也降不下去。原因出在 α——这一节说清它该怎么给。
前面六节都站在一条没写出来的假设上：动作的结果是确定的。真机上不是。这一节只改这一条。
```

反面：

```
这一节介绍收敛性。            ← 目录，不是承接：没说上一节缺了什么
承接上一节。                  ← 等于没写
§5 的结论指向下一步。          ← 指代不说全，读者不知道是哪个结论
```

三条硬要求：

1. **中间那一段不能省**。承接行的价值全在「上一节留下了什么缺口」，缺口没写就退化成目录。
2. **承接行说过的，正文首段不许再说一遍**。动手写的时候常发现首段本来就在承接——
   那就把那句整个挪进 `.lead`，正文从内容开始。
3. **习题、本章小结不写**。它们的位置不需要解释。

自检：随手翻到任意一节的标题，读者能不能立刻回答「**为什么这里会有这一节**」。
写不出来通常不是行文问题，是**这一节的位置错了，或者本来就该并进上一节**。

## 重复：同一件事只讲一处，其余回指

同一个结论在两处各讲一遍，读者不会觉得「巩固了」，只会觉得「刚才不是说过吗」。规矩是：

- **信息最全的那一处留全文**，其余全部改成回指，并且**回指时要带上新增的东西**。
  「§3 开头那句『新的一版盖掉旧的』说的就是这件事：k 是覆写的次数，不是表的层数。」
- **本章小结可以重述结论，但不许照抄句子**。抄回来的长句要压成更短的断言。
- **展望块（`.nx`）只提问题、点名下一节，不要把下一节的论证讲完**。
  下一节的正文会再讲一遍，两边必然打架。
- 跨课同理：上一课已经讲过的推理，这一课只写一句回指 + 这一课新增的那部分。

## 命名：标题要经得起「本页目录」测试

把一课所有 h2 抽出来单列成一列，读一遍——要像教材目录，不像一串摘要。判据与样本见 SKILL.md。

核心：**直接写术语，不加解释性前缀**。

| 该写 | 不该写 |
|---|---|
| 策略评估 | ~~策略评估：给定策略的值表~~ |
| 值迭代 | ~~值迭代：截断评估的极端情形~~ |
| 回报与折扣 | ~~两个旋钮：方差与偏差~~ |
| 示例：小网格世界 | ~~一间仓库，一张表~~ |
| 本章小结 | ~~六句话收尾~~ |

反例（都不要）：

- 设问式：「V 到底是什么」「稳定性去哪了」
- 动作式：「把值表算出来」「不等评估收敛就动手」
- 场景式：「一间仓库，一张表」「一条五格链上的完整计算」
- 评论式：「三件套的账：轮数少 ≠ 算得少」
- 前缀式：「方程：……」「线性化：……」「边界：……」——冒号只留给「示例：」「实验：」
- 口头禅：「先把 X 说死」「先把话说白」「说穿了」

## 定义一个记号：术语。定义句。

写法固定成「**术语**。一句定义。」——先给它在教材里的名字，再用一句话说它**是什么**：

> **奖励信号**。环境在每一步发给智能体的数字，它定义了目标。
> **策略**。智能体的决策规则，把状态映射到动作。
> **最优值函数**。从 s 出发、此后一直按最优走法走，今后能拿到的折现总回报。

定义句里**不举本课的具体值**。「本课恒为 −1」「本课取 0.9」属于算例，写进正文或算例表，不写进定义。
符号表就两列：**记号 | 含义**。不要「什么类型」「在这个例子里是什么」这种列——那是正文的活。

## 符号

- 每个变量第一次出现当场定义，给读法、类型、取值范围。
- 全书一套符号，不中途换字母；`V^π` / `V⋆` / `V_k` 三者含义固定，不混用。
- 公式给完立刻逐项拆解，或用下花括号标注。
- 不写「显然」「容易看出」——把那一步写出来。

## 开场句式

- 「这一课不推公式。我们只做一件事：**把一个具体的数刷出来**。」
- 「前面三课的每一个数字，都是算出来的……这一课把模型拿走。」
- 「你已经把 DQN 拆完了，只是还没人告诉你。」
- 「你现在手上的整条流水线，最后一步都是这个：a* = argmax Q(s,a)。」——先摆出读者已有的东西，再指出它在哪断掉。

## 破误解优先

新概念不从定义讲起，从**读者大概率的错误理解**讲起：

- 「V_k 不是什么「迭代中间量」。它是一个**独立成立的、精确的答案**——只不过回答的是「只剩 3 步」这个问题。」
- 「前 4 遍的 0 是**正确答案**，不是「没算准」。」
- 「一个决定性的论据，说明 k 不可能是时刻。」

但要破的必须是**读者真会那么想**的理解。三条红线：

- 不要立一个讲义里从没出现过的说法再去反驳它（「顺带纠一个常见的说法：不是……」——那个说法哪来的？）。
  同一件事正面说就够了：「三个里只有两个在取最大：策略改进和值迭代。」
- 不要评论已经删掉的内容。读者看到的是当前这一版，他不知道以前写过什么。
- 「常见误解」「很多人以为」这类开场，一课最多一次；用多了整本书像在跟人吵架。

## 白话复述

每个公式后面接一句「翻译」，句式固定：

- 「这个式子读一遍就够了：误差不是「在原地缩小」，而是「从下游搬过来、顺便打了个 γ 折」。」
- 「「值迭代」翻译成大白话就是：把预算一路加上去，加到再加也没用。」
- 「这里没有任何近似、没有任何假设，就是把一个无穷和重新分组。」
- 「递归把无穷次加法换成了有限次、每次一步的迭代。**这就是 Bellman 方程真正买到的东西。**」

## 承认难点和意外

- 「然后是本课最让我意外的一个数字。」
- 「一个值得记住的对立。」
- 「但代价请看清楚。」
- 「这是真正的卡点，也是最值得想明白的一步。」
- 「务必盯住最后那个条件——这是最容易读错的地方。」
- 「但请注意这两条只是充分条件。」

## 结论的写法

结论要**可执行、可反驳**，不要「很重要」「非常关键」：

- ✅「如果起点离奖励有 50 步，你至少要刷 51 遍才第一次看见非零值。稀疏奖励难学，难就难在这里，跟算法聪不聪明无关。」
- ✅「贪心策略远在值函数收敛之前就已经最优了。」
- ✅「「要不要衰减」取决于目标有没有噪声，**不取决于算法叫什么名字**。」
- ❌「值迭代是一个非常重要的算法。」

## 加粗与强调

| 手段 | 用在哪 |
|---|---|
| `<strong>` | 可执行的结论、判断句。一段最多一处 |
| `<b>` | 数字、块首断言、表格里的关键值、图题里的结论词 |
| 「」 | 讲义自己起的名字：「刷一遍」「上一稿」「只剩 k 步」 |
| 『』 | 「」之内再套一层引号时用：「不是『没算准』」 |
| `<code>` | 函数名、文件名：`solve_discrete_are`、`arm_dp.py` |
| `<em>` | 极少用，用于自问自答里的那个问句 |

术语第一次出现**不加粗**，用公式或 `<code>` 呈现；加粗留给结论。

## 收尾节

固定叫「N 句话收尾」，编号列表，每条 `<b>一句断言。</b>` 打头，后面补一句解释：

```html
<ol>
<li><b>没模型不改变任何理论，只改变一件事：期望算不出来。</b>于是「精确期望 + 直接赋值」变成「一个样本 + 挪 α 那么多」。</li>
<li><b>DP 是「整张表一次一次刷」，TD 是「一条轨迹一条轨迹漂」。</b>……</li>
</ol>
```

## `<footer>` 两件事

```html
<footer>
下一课进 Stage 5：策略梯度。到目前为止你学的全是「学值，然后 argmax 出策略」——那条路在连续动作上直接断掉。<br>
本课所有数字都是跑出来的：消融的四格、打滑版 DP 的重算、以及 Double DQN 那个带符号偏差。
</footer>
```

1. **下一课去哪，以及为什么是这个顺序**（依赖关系，不是时间表）。
2. **数字与图的来源脚本 + 重跑耗时**（「整跑约 4 分钟」）。

## 中文排版

- 中英文/数字之间留一个空格：「跑 3721 格」「用 Fourier basis（阶数 3~5）」。
- 全角标点；破折号用 `——`；省略号用 `…`。
- 数字带精度并统一小数位；比值写成「106 倍」「11 倍」而不是「一个数量级」。
- 单位与口径讲清楚：「44 小时真机时间」「16 万步」「约 90 秒重跑」。

## 禁忌

- 不写没跑过的数。
- 不写「显然」「不难看出」；难就说难。
- 不在同一课里换符号而不公告。
- 不用没有信息量的图题。
- 不堆术语开场——术语要等到读者已经看见那个数字之后才出现。
- **不写「第 N 课 §M」这种跨章坐标。** 读者手上没有那本书的目录，一个「第 1 课 §4.4」等于让他中断阅读去翻页。
  三条出路，按优先级：① 把那句话直接说完，别引；② 写「上一课 / 下一课」；③ 写内容不写编号（「后面讲蒙特卡罗与时序差分那一课」）。
  本章之内的 `§N` / `§N.M` 不受此限——它们会被 `book.js` 变成可点、可返回的链接。
- **不引用还没写出来的章节。** 路线图上排着不等于读者点得开。
- 不在两课里各自完整定义同一个记号。第一次出现的那一课负责定义，后面的课只回忆一行。
- 不在同一课里对同一个量用两套记号（`s_A`–`s_E` 和 `s_0`–`s_4` 不能并存，插图里的标注也算）。
- 正文里不用 ASCII 直引号 `"`，一律 `「」`。
- **不用记账 / 买卖那一套比喻替技术词。** 「当场的账」「未来的账」「四笔账」「总账」「算它们各自的账」——
  「账」到底是什么？读者答不上来。同一句话本来就有准确的说法：
  「当场的账」＝ **这一步的奖励**，「未来的账」＝ **打折后的未来值**，「四笔账」＝ **四个动作值**，
  「总账贵了 10 倍」＝ **更新次数多了 10 倍**。同族的还有：值多少钱、不要钱、报价、买来的、免费、白给、红利、天花板。
- **算子就叫算子。** 不写「一台机器吃进一张表、吐出一张新表」「把两张表喂给 T⋆」——
  写「输入一张值表，输出一张新的值表」「把 T⋆ 作用在这张表上」。
  生动的动词一旦替掉了准确的动词，读者学到的就是那个动词，不是那个概念。
- 描述发散、变慢、失效，直接说发散 / 变慢 / 失效，不写「炸了」「出事」「甩出去」「护栏」「埋线」。
- **不用含糊的评价词。** 「很干净」「很漂亮」「很聪明」「很厉害」「不神秘」「划算」「值多少钱」——
  遮住这个词，读者说不出那里到底好在哪。把它换成具体那一句：
  「值迭代赢得很干净」→「52 个状态-动作对、7 遍扫描、误差有界、什么时候能停也算得出来」；
  「差得最狠的那一格」→「差得最大的那一格」；「轮数涨得这么厉害」→「轮数涨了这么多」。
- **「当然」「确实」和「显然」是同一家。** 「一步都不许走，当然一分也拿不到」——把「当然」去掉，
  句子一个字都不缺。只有真正在让步时才留（「执行的时候确实是往前走，但算的时候不能」）。
- **`<footer>` 里点名的脚本必须真的在仓库里。** 写了「由随附的 `foo.py` 生成」却没有这个文件，
  是把一句核对不了的话摆在读者面前。
